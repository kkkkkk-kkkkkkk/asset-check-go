# asset-check

安全设备资产台账（CSV）校验与规范化命令行工具。Go 1.21+，**仅标准库**，校验逻辑与文件 IO 完全分离。

针对现实里那种「格式乱、错误多」的台账：同一批 IP 写法不统一、设备类型中英混写、工号缺字、端口写着 0 或 65536、整行空白、换行符带空格。工具把它拆成两个产物——一份**干净可直接入库的规范化清单**，一份**精确到行号和列名的问题报告**。

## 用法

```bash
# 编译
go build -o asset-check .

# 体检（有问题也返回 0，适合先看报告）
./asset-check -in testdata/asset_raw.csv -out normalized.csv -issues issues.csv

# 卡口（有任意 error 即非零退出，适合放进 CI / 定时任务）
./asset-check -in testdata/asset_raw.csv -strict

# 换一套客户自己的规则
./asset-check -in raw.csv -rules rules.default.json -strict
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-in` | 必填 | 输入 CSV 路径 |
| `-out` | `normalized.csv` | 规范化清单输出 |
| `-issues` | `issues.csv` | 问题报告输出 |
| `-rules` | 内置默认规则 | 规则 JSON 路径 |
| `-strict` | false | 有 error 时退出码 1 |
| `-keep-invalid` | false | 把有错误的行也写进规范化清单 |
| `-quiet` | false | 只返回退出码，不打印摘要 |

退出码：`0` 正常；`1` strict 模式下存在 error 级问题；`2` 参数、文件或规则本身有问题（例如表头映射不上）。

## 规则可配置

字段口径放在 `rules.default.json`，改规则不需要改代码：

- `columns`：CSV 表头（去空格、转小写后）到业务字段的映射。客户表头叫「IP地址」「工号」「Port」也能认。
- `device_types` / `device_type_aliases`：允许的设备类型清单，以及 `FW→防火墙`、`SW→交换机` 这类别名归一。
- `owner_id_pattern`：工号正则。
- `port_min` / `port_max` / `port_optional`：端口区间，以及是否允许空端口（例如非 TCP 设备）。

## 输出

规范化清单（只含通过校验的行，按首次出现顺序）：

```
IP,设备类型,负责人工号,端口
10.10.0.5,交换机,B2001,22
10.10.0.6,防火墙,A1002,8080
```

问题报告（一行一个问题，行号与原始 CSV 对齐，表头算第 1 行）：

```
行号,列名,严重度,原始值,问题描述,建议值
2,IP,error,192.168.001.010,不是合法 IPv4…；看起来是 192.168.1.10,192.168.1.10
4,IP/端口,warning,10.10.0.5:22,与第 3 行的 IP+端口 重复,按首次出现保留
7,负责人工号,error,1234,不符合工号格式 ^[A-Za-z]{1,2}\d{3,6}$,
```

几个刻意的设计取舍：

- **前导零一律判错**（`192.168.001.010`），因为 `010` 在不同解析器里可能是八进制；能猜出本意时在「建议值」里给 `192.168.1.10`，猜不出就留空——宁可没有建议，也不给错建议。
- **去重键是「规范化后的 IP + 端口」**，所以 `10.10.0.5` 和 ` 10.10.0.5 ` 会被认成同一条；但同一 IP 不同端口不算重复。
- **IP 或端口本身有问题时不参与去重**，避免拿两条残缺记录去比。
- **规范化清单只写通过的行**，错误行集中在报告里，避免脏数据二次流入。

## 投产前需要客户确认的三个口径

代码里的默认值是**占位**，不是客户资产台账的真实规则：

1. 设备类型的合法集合（现在给的是 12 个常见类）；
2. 工号格式（现在是「1–2 个字母 + 3–6 位数字」）；
3. 空端口是否合法（现在判为错误）。

这三项确认后，只改 `rules.default.json`，逻辑与测试都不用动。
